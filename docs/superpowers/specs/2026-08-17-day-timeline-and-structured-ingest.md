## 1. 产品一句话

用户对着时间说话。模型一次想清楚「记还是问、写什么标题、落在哪一刻」。记录则立刻进当天时间线；一天可以有很多条，先看标题，再点进详情。

## 2. 已锁定决策

| 项 | 决定 |
|----|------|
| 导航 | **欢迎混合流（根）** → 月历或日时间线 → **日记详情全屏页**（见 `2026-08-19-welcome-home-design.md`） |
| 日列表 | 按 `startAt` 升序；每条默认只显示时刻 + 标题 + 红/绿 |
| 详情 | 标题、整理后正文、原话、地点、人物、类型、完成态；可改完成态 |
| 意图 | MiniMax Chat **一次 JSON**；客户端不再用 `InputIntents` 关键词路由 |
| 记录 | `intent=record` 且 `need_more=false` → **自动写 Room** |
| 成功反馈 | 居中/底部 **标题弹窗约 3 秒** 后消失；若用户正在该日落点日，时间线插入新条 |
| 检索 | `intent=recall`：P1 用提取字段做 **本机 FTS/时间过滤**，结果呈现在首页 **结果卡**（不是独立精美检索页） |
| 补全 | 时间/地点/人物 **缺 ≥2 项**才追问（每轮一项，最多 2 轮）；可「先记下」。见 `2026-08-19-clarify-and-edit.md` |
| 完成态 | 写入时 `done = startAtMillis <= now`（Asia/Shanghai）；详情里可手动覆盖 |
| 时间缺省 | 模型提不到时间 → **当前时刻** |
| 地点缺省 | 提不到 → 试定位；拒绝/失败 → 空字符串 |
| 人物缺省 | 提不到 → 空列表 |
| 语音听写 | 继续本机 **Vosk** |
| 语音播报 | MiniMax TTS 同 Key 可用，**P3** |
| Embedding | 本机 BGE-small-zh ONNX；日期解锁日页；无日期语义+FTS |
| Mutate | **二期**；删改走详情页按钮 |
| 预览确认 | **不做** |

不做（本规格外）：闹钟、云同步、原始录音文件、照片、账号、独立检索大页动效、TTS。

## 3. 信息架构

```
欢迎页（根）+ 底部语音
  ├─ 顶栏「月历」 ──────────► 月历页
  │                            ├─ 点日期 ──► 日时间线页 ──► 日记详情页
  │                            └─ 返回欢迎
  ├─ 点一条 ─────────────────► 日时间线页 ──► 日记详情页（返回欢迎）
  ├─ 记录成功 ──► 3 秒标题弹窗 ──► 刷新欢迎流；若落点日已打开则刷新时间线
  ├─ 检索 ──────► 当前页结果卡（标题列表，可点进详情）
  └─ 追问 ──────► 草稿卡内显示模型问题，继续说话
```

月历不是根界面。打开 App：先欢迎页。月历仍默认高亮 **今天**（Asia/Shanghai）。日时间线打开时月历不在屏幕上。从日页返回时按来源回到欢迎或月历。

## 4. 日时间线 UX

一屏一件事：**这一天按时间发生了什么**。

- 顶栏：`M月d日 · 星期` + 返回。副文案：条数，如「3 则」。
- 主体：左侧细时间轴，右侧每条一行：
  - 时刻 `HH:mm`（无时刻语义时仍显示模型给出的默认钟点）
  - **标题**（模型总结，一行，过长省略）
  - 右侧小圆点：绿=已完成，红=未完成
- 空态：短句「这一天还没有记录」+ 不堆按钮。用户用底部球补记（日页也保留球，或返回首页再记——**日页保留同一套底部球**，记完后若 `start_at` 落在当天则插到列表顶部对应时刻）。
- 动效（必须有，且克制）：
  1. 页进入：列表项 stagger fade+上移 40–80ms 间隔
  2. 新插入：该项从 0.92 scale + fade 进入
  3. 点行：轻微按压缩放后推进详情（shared-ish：标题字号过渡即可，不做复杂 shared element）
- 禁止：卡片墙、统计条、第一屏塞满元数据。

详情页：大标题 + 完成态色条 + 正文 + 原话折叠 + 地点/人物/类型一行辅助信息。开关改 `done`。

## 5. 结构化模型契约（P1 核心）

客户端发 **一次** Chat Completions（**不要 tools**），`thinking` 关闭。请求带：

- `now` ISO-8601 Asia/Shanghai
- 用户原话（及多轮追问时的历史：user/assistant 交替）
- 当前记事本 id/name
- 可选：粗定位字符串（若已授权）

模型 **只输出一个 JSON 对象**（可包在 markdown 代码围栏里，解析器要剥掉）。Schema：

```json
{
  "intent": "record | recall | clarify",
  "need_more": false,
  "clarify_question": null,
  "entries": [
    {
      "title": "短标题，不超过 20 字",
      "start_at": "2026-08-17T15:30:00+08:00",
      "place": "",
      "people": [],
      "diary_type": "life",
      "body": "整理后的日记正文",
      "raw": "用户原话摘录或全文"
    }
  ],
  "recall_query": {
    "time_from": null,
    "time_to": null,
    "diary_type": null,
    "keyword": null,
    "title_hint": null
  }
}
```

规则：

- `record`：`entries` 至少 1 条；一段话多件事拆多条。
- `recall`：`entries` 可空；填 `recall_query`。P1 用这些字段筛本地库，结果卡展示命中标题。
- `clarify`：`need_more=true`，一句中文短问；**带回当前 `entries` 草稿但不写库**，直到用户说全或点「先记下」。
- 时间：用户没说则 `time_explicit=false`，`start_at` 仍可填现在供草稿展示。
- 地点空、人物空列表表示未说。缺 ≥2 项才追问。

**完成态不交给模型决定。** 入库前客户端：`done = Instant.parse(start_at) <= Instant.now()`。

| 字段 | 类型 | 含义 |

## 7. 客户端流程

```
松手/点「分析」
  → 若在追问中：把新输入接到 history
  → MiniMax 结构化调用
  → 解析 JSON
       ├─ clarify → 显示问题，保持草稿
       ├─ record  → 写库 → 3 秒标题弹窗 → 关草稿 → 刷新月点/日列表
       └─ recall  → 本地过滤 → 结果卡（标题列表）→ 关草稿
```

去掉：`InputIntents.classify` 主路径、Ingest 预览 Sheet、ingest 的多步 tool loop。

Agent 工具循环仍可用于 **P2 复杂检索**；P1 检索只用 SQL/FTS。

## 8. 定位

`ACCESS_COARSE_LOCATION` 可选。仅当模型 JSON 的 `place` 为空且系统已授权时填入逆地理或「经纬度粗字符串」；未授权不强弹（第一次记录成功后可在设置里开）。P1 允许 place 一直为空。

## 9. 验收（P0+P1）

P0

- 点今天进入全屏日页，不是 BottomSheet。
- 多条按时间排列，默认只见标题；点进详情见全文。
- 返回后才能点其他日期。
- 今天及过去时刻写入后为绿；未来时刻为红（用手动改详情开关验证覆盖）。

P1

- 「下了班去喝了咖啡」→ 自动出现一条，标题为模型总结，弹窗约 3 秒，时间线可见。
- 「明天下午三点见客户」→ 红、落在明天。
- 一次两件事 → 两条标题。
- 信息不足（例如只说「帮我记一下」）→ 追问，不写库。
- 「上周喝了什么」→ 不写库；结果卡列出筛到的标题（可少、可空态「没有找到」）。
- 无 Key / 解析失败：不写，草稿还在。

## 11. 风险

- 模型偶尔输出非 JSON：解析器要容错；失败可重试一次「只输出 JSON」。
- Destructive migration 清空日记：仅 debug 可接受；告诉用户重装后旧数据没了。
- 一次调用延迟仍有 1–数秒：只有一条进度，文案「正在整理…」，禁止双进度、禁止二次分析。
- MIX 3 性能：列表不要每帧重绘；stagger 条数上限 30。
