# 首次欢迎页 · 工作区批量管理 · 状态点规则

日期：2026-08-22  
状态：已与产品确认，待实现计划

## 目标

一次交付三件独立但相关的体验改动：

1. **首次欢迎页**：教学向，说明「按住说一句就能记」
2. **工作区批量管理**：编辑工作区时可管理其下日记并批量移入废纸篓
3. **状态点规则**：列表里每条日记都显示完成/未完成点

## 非目标

- 欢迎页真录音或强制记第一笔
- 欢迎页选工作区 / 每次启动再挡一次
- 首页多选模式、批量改时间、批量改工作区、硬删除绕过废纸篓
- 改动用户已手改的设置文案（个人资料 / 备份恢复 / 关于语曰等）

## §1 首次欢迎页

### 触发

- 本地持久化标记 `welcomeSeen`（或等价名），默认 `false`
- `false`：启动后先显示欢迎页，再进现有导航/工作区首页
- 用户完成欢迎后写 `true`；之后启动直接进工作区
- 清数据 / 重装后会再出现

### 布局（单屏）

1. 品牌或一句欢迎文案（例如「用嘴记下你的时间」）
2. 中央大语音钮（示意，非真录音）
3. 底部主按钮「开始使用」

视觉语言对齐现有首页氛围（时段光、主色），避免另起一套皮肤。

### 交互

| 控件 | 行为 |
|------|------|
| 语音钮 | 轻提示：「到首页按住说一句」→ 进入工作区，并标记 `welcomeSeen=true` |
| 「开始使用」 | 直接进入工作区，并标记 `welcomeSeen=true` |

### 明确不做

- 真按住录音、调用模型、写入日记
- 强制必须点语音才能离开
- 多步向导

## §2 工作区管理 + 批量日记

### 入口

设置 → 工作区管理 → 某工作区「编辑」进入**工作区详情**（不再只是改名弹窗）。

「删除」工作区逻辑保持现状：其下日记软删进废纸篓；至少保留 1 个工作区。

### 工作区详情

1. **名称**、**颜色**：可改，保存即生效（沿用现有 `updateNotebook`）
2. **管理日记**：进入该工作区日记列表（批量模式）

### 日记列表（批量）

- 数据：该 `notebookId` 下未删日记，时间倒序
- 默认多选：左侧勾选；顶栏显示已选数量
- 底部主操作：**移入废纸篓**（软删除，与现有删除一致，可在废纸篓找回）
- 点单条：进入详情/编辑（与首页一致）
- **首版只做批量删除**；不做批量改时间、批量移动工作区

### 导航示意

```
Settings → 工作区管理
  → 编辑 → WorkspaceDetail（名称/颜色 + 管理日记）
       → WorkspaceEntries（多选列表 → 批量废纸篓）
  → 删除 → 确认对话框（现状）
```

## §3 状态点规则

### 问题根因（已核实）

缺绿/橙点**不是**长标题裁切。当前 `WelcomeFeedRow` 用 `MemoryKind.isTaskOrEvent`：仅 `diaryType ∈ {task, plan, meeting}` 或 `startAt` 在未来才显示点。普通生活日记故意不显示。

### 新规则

- **首页列表、日时间线、搜索列表**：每条日记都显示完成点
  - 已完成 → 绿色（`done`）
  - 未完成 → 橙色/待办色（`pending`）
- 点圆点切换 `done`（沿用 `setEntryDone`）
- 布局继续用固定日期列宽 + 圆点 `requiredSize` 点击热区，避免长标题挤掉圆点

### 日历圆点

- 有任意未完成日记的日期 → 待办色高亮
- 仅有已完成 → 完成色（若现有双态保留则对齐；否则至少「有未完成」优先）

### 明确改动点

- 去掉列表行上对 `MemoryKind.isTaskOrEvent` 的显示门槛（或改为恒 true）
- `MonthDots` / 等价逻辑与「任意未完成」对齐
- `MemoryKind.isTaskOrEvent` 若仍被别处用于语义分类可保留，但**不再**作为列表是否显示完成点的条件
